## Summary

One large fix release. The published renderer now honours the documented `screenshot`, `text`, `position_preset`, and rich-`background` object overrides; the `output_device` enum no longer crashes on advertised IDs; `textColor` semantics are correct; AI-disabled and 3D-not-implemented states now surface explicit `warnings` in the tool response.

## Per-issue summary

### #2 — `background: undefined` overrides template defaults — fixed (server)

`tools/render.ts` no longer writes `background`, `screenshot`, `text`, `reference_image`, `positionPreset`, or `backgroundPreset` onto the decision when the user didn't supply them. The frontend's spread merge `{ ...defaults, ...decision }` no longer clobbers template defaults with `undefined`.

### #3 — 3D renderer is a stub — clear `warnings` field added (server)

Both `render_screenshot` and `generate_screenshot` now emit a `warnings: [string]` array in the response when `mode === "3d"` or `device === "iphone-3d"`. The warning explicitly tells callers that the output is a 2D fallback and that real WebGL device frames ship when `.glb` device models land. The actual 3D implementation is deferred to a future rc.

### #4 — `screenshot` overrides not consumed — fixed (renderer)

The `clean-minimal` template now reads `decision.screenshot` and applies:

- `scale` (% canvas width), `x`, `y` (% canvas positions) — overrides for sizing and placement
- `rotation` (degrees, around device centre) — applied via canvas transform
- `cornerRadius` — overrides default 8.5% radius
- `glow` (`{ enabled?, color, intensity, size }`) — second-pass shadow halo
- `shadow` (`{ enabled?, color, opacity, blur, x, y }`) — overrides the default soft drop shadow

Layout authoring matches the design-templates skill: `scale: 73, x: 50, y: 80` works exactly as documented. Fields not yet implemented (`rotation3D`, `decoration`, `frame`) land alongside real 3D.

### #5 — `text` overrides not consumed — fixed (renderer)

The template reads `decision.text` and applies:

- `headlineSize`, `subheadlineSize` (px authored on a 1320-canvas, scaled proportionally to the actual canvas width)
- `headlineColor`, `subheadlineColor`
- `headlineWeight`, `subheadlineWeight`
- `headlineFont`, `subheadlineFont`, `font` (top-level fallback)
- `headlineMaxWidthPct`
- `headlineLetterSpacing`
- `headlineItalic`, `headlineUnderline`
- `headlineHighlightWord` + `headlineHighlightColor` + `headlineHighlightStyle: "color" | "pill"` + `headlineHighlightPillTextColor`
- `headlineTextAlign`, `subheadlineTextAlign`
- `position`, `offsetY` (% of canvas height)
- `lineHeight`

Fields not yet implemented (`headlineGradient`, `headlineStrikethrough`) land in a future rc.

### #6 — `position_preset` rotation/tilt not applied — fixed (renderer)

`computeLayout()` now reads `PRESET_CATALOG.positionPresetDetails[decision.positionPreset]` and applies the preset's `scale`, `x`, `y`, and `rotation`. Explicit `decision.screenshot.{scale,x,y,rotation}` overrides win over the preset. `tilt-left` / `tilt-right` produce visibly different output from `center`.

### #7 — `text_color` vs `mode` semantic mismatch — fixed (renderer)

The pre-fix code compared `decision.mode === "dark"` for the dark-text branch — but `mode` is `"2d" | "3d"` in the server contract, so the path was dead. New normaliser maps `textColor` ("light"/"dark") with the correct semantics: `text_color: "light"` → render LIGHT (white) text; `text_color: "dark"` → render DARK (black) text. Legacy `mode: "light"/"dark"` (light/dark THEME) is still honoured as a fallback so old callers don't break.

### #8 — `generate_screenshot` silent AI fallback — fixed (server)

When the AI layer falls back to deterministic defaults (no `ANTHROPIC_API_KEY`, client doesn't advertise sampling), the tool now appends a `warnings: [string]` field explaining that `hints` / `app_name` were ignored and pointing at `docs/llm-strategy.md`. The previous `reasoning: "deterministic fallback..."` string was buried.

### #9 — TypeError on rich `background` object — fixed (renderer, rc.5)

Was already fixed in rc.5 via the `normalizeDecision` layer that classifies `decision.background` into string-preset vs rich-object before any field-method is called. Smoke covers the object path with `{ type: "gradient", gradient: { angle, stops } }` and confirms it renders without throwing.

### #10 — `output_device` enum unknown to PRESET_CATALOG — fixed (renderer)

`PRESET_CATALOG.outputDevices` + `canvasDimensions` now lists every device key the server schema advertises:

- `iphone-6.9` → 1320 × 2868 (App Store required for 6.9")
- `iphone-6.7` → 1290 × 2796
- `iphone-6.5` → 1242 × 2688
- `iphone-5.5` → 1242 × 2208
- `iphone-15-pro-max` → 1290 × 2796 (alias)
- `google-pixel-8` → 1080 × 2400

Smoke iterates all 6 and asserts each renders without throwing.
